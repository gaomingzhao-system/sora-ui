# Translations and right-to-left

## The contract

Components never import an i18n library. They read one small interface from the nearest `UiProvider`:

```ts
interface UiTranslator {
  /** BCP 47 tag; must be reactive (a getter over reactive state). */
  readonly locale: string
  /** The translated message, or `undefined` when the key is unknown. */
  translate(key: string, params?: Record<string, string | number>): string | undefined
}
```

Without a provider, or when `translate()` returns `undefined`, the built-in **English** messages are
used. A missing translation therefore degrades to readable English, never to a key.

## Messages

The library has 59 messages (button names such as "Close", status text such as "Loading options",
generic validation messages). They are flat keys with `{name}` placeholders only: no linked messages,
no plural pipes, no HTML. Counts are phrased number-neutrally ("Results available: {count}") so that
every locale has exactly the same keys.

| Import                                 | Content                                                      |
| -------------------------------------- | ------------------------------------------------------------ |
| `@your-scope/ui/locales/<locale>`      | plain strings, for any translator                            |
| `@your-scope/ui/i18n/locales/<locale>` | the same messages precompiled for vue-i18n / petite-vue-i18n |

Locales: `en`, `ja`, `ar` and `pseudo` (accented, lengthened English with a `en-XA` flavour, for
spotting untranslated or clipped text). `pnpm check:locales` verifies key and placeholder parity, that
every message compiles, that ja and ar are really translated, and that every key used in the sources
exists.

## With petite-vue-i18n

```bash
pnpm add petite-vue-i18n
```

```ts
// i18n.ts
import { createUiI18n } from '@your-scope/ui/i18n'
import english from '@your-scope/ui/i18n/locales/en'

export const ui = createUiI18n({
  locale: 'en',
  fallbackLocale: 'en',
  // Library messages and your own, in one dictionary per locale.
  messages: { en: { ...english, 'app.title': 'My app' } },
  // Other locales are fetched the first time they are requested.
  loadLocale: async (locale) => ({
    ...(await import(`./locales/ui-${locale}.ts`)).default,
    ...(await import(`./locales/app-${locale}.ts`)).default,
  }),
})
```

```vue
<UiProvider target="document" :locale="ui.locale.value" :translator="ui.translator">
  <App />
</UiProvider>
```

`createUiI18n` returns the petite-vue-i18n instance (`i18n`, install it with `app.use()` if your own
components call `useI18n()`), the `translator` for the provider, a writable `locale` ref,
`setLocale(locale)` (loads the messages if necessary, then switches; concurrent calls share one load
and a failed load can be retried) and `hasLocale(locale)`.

If you already have an instance, `createPetiteTranslator(i18n)` adapts it. Only the instance's global
composer is used, so no second instance is created and nothing depends on a component instance.

### Dropping the runtime message compiler

The `i18n/locales/*` modules contain message ASTs compiled at build time with
`@intlify/message-compiler`. An application whose own messages are precompiled as well can remove the
compiler from its bundle:

```ts
// vite.config.ts
define: {
  __VUE_I18N_LEGACY_API__: 'false',
  __VUE_I18N_FULL_INSTALL__: 'false',
  __INTLIFY_DROP_MESSAGE_COMPILER__: 'true',
}
```

[`apps/consumer`](../apps/consumer) is built this way and tested in a browser by `pnpm verify:consumer`.
[`scripts/compiled-messages-plugin.ts`](../scripts/compiled-messages-plugin.ts) is the small
Vite/Rolldown plugin the library and the gallery use to precompile `?compiled` imports.

## Without an i18n library

```ts
import { ref } from 'vue'
import { createUiTranslator } from '@your-scope/ui'
import ja from '@your-scope/ui/locales/ja'

const locale = ref('ja')
const translator = createUiTranslator({ locale, messages: { ja }, fallbackLocale: 'ja' })
```

`createUiTranslator` reads `locale` and `messages` lazily, so reactive inputs update the interface. A
regional tag falls back to its language (`de-AT` → `de`).

## Locale, numbers and direction

`UiProvider` props:

| Prop         | Effect                                                                  |
| ------------ | ----------------------------------------------------------------------- |
| `locale`     | sets `lang`, drives `Intl` number formatting, and implies the direction |
| `dir`        | explicit `ltr` / `rtl`, overriding the locale's direction               |
| `translator` | the messages                                                            |

Numbers the components render (pagination, table cells, counters) go through `Intl.NumberFormat` for
the active locale. `useUiLocale()` gives your own components the same `t`, `locale`, `dir` and
`formatNumber`.

### Right-to-left

Direction is handled by the platform wherever possible:

- All spacing, borders, alignment and positioning use logical properties (`margin-inline`,
  `inset-inline-end`, `text-align: start`), so layouts mirror without overrides.
- Anchor-positioned popups use logical `position-area` values.
- Only **directional** icons (chevrons, arrows) mirror, through `:dir(rtl)`; a check mark or a search
  glass does not.
- Arrow keys follow the visual order: in a right-to-left tab list, ArrowLeft moves to the next tab.
- A drawer on the `end` side docks to the left edge.

A provider can scope a right-to-left island inside a left-to-right page (the gallery's Accessibility
page does). Popups rendered in the top layer keep their DOM ancestors, so they inherit direction,
language and tokens from the provider around them.

## Adding a locale

1. Copy `packages/ui/src/locales/en.ts`, translate every value, keep every key and placeholder.
2. Add the matching `packages/ui/src/i18n/locales/<locale>.ts` (one import with `?compiled`).
3. Add the locale to `LOCALES` in `scripts/sync-exports.ts` and `packages/ui/tsdown.config.ts`, run
   `node scripts/sync-exports.ts`, and add it to `scripts/check-locales.ts`.
4. `pnpm check:locales && pnpm build && pnpm check:package`.
